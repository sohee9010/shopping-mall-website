## P1-a. 주문 금액을 클라이언트가 임의로 지정 (489,000원 상품을 100원에)

- **원본 코드 위치**: v0-baseline src/pages/CheckoutPage.tsx:173 (클라이언트가 계산한 total_amount를 그대로 저장)
- **정상이라면**: 주문 금액은 서버가 DB의 상품 가격으로 계산해야 하고, 클라이언트가 보낸 금액은 무시해야 한다
- **실제 결과**: 앱 경로로 100원 주문 → 저장된 금액 492,000원 / 주문 테이블 직접 insert → 거부됨
- **판정**: 🟢 재현 안 됨

- **정상이라면**: 서버가 결제사(Toss)에 승인 여부와 금액을 확인한 뒤에만 결제완료 주문이 생겨야 한다

- **정상이라면**: 본사가 입점을 승인하면 신청한 계정이 바로 그 브랜드의 입점사로 상품을 등록하고 주문을 볼 수 있어야 한다
- **실제 결과**: 가입 + 입점 신청 → 본사 승인 → 신청자 역할 'customer', 주문 조회 거부: 입점사 관리자만 조회할 수 있습니다 (계약 중인 브랜드만)
- **판정**: 🔴 재현됨

## P28. 결제되지 않은 주문·취소된 주문이 대시보드 매출에 포함

- **원본 코드 위치**: src/admin/hq/pages/HQDashboard.js:82-95 (이번 달 orders.total_amount 합계, 상태 무관), src/services/dashboardService.ts (화면에서 집계)
- **정상이라면**: 매출은 결제가 완료되고 취소·반품되지 않은 상품 금액만이어야 한다
- **실제 결과**: 결제대기 주문(219,000원) 생성 → 이번 달 매출 1,529,000원 → 1,529,000원
- **판정**: 🟢 재현 안 됨

## P25. 입점사가 등록한 상품이 본사 검수 없이 쇼핑몰에 노출

- **원본 코드 위치**: src/admin/merchant/pages/Products.js:288 (등록 시 status: forsale), 0002 products 정책(상태 검사 없음)
- **정상이라면**: 입점사가 등록한 상품은 검수대기로 저장되고, 본사가 승인하기 전에는 고객에게 보이지 않아야 한다
- **실제 결과**: status=forsale로 등록 → 저장된 상태 'pending', 비로그인 고객 조회 안 됨 / 검수대기 상품을 입점사가 판매중으로 변경 → 고객 조회 안 됨
- **판정**: 🟢 재현 안 됨
